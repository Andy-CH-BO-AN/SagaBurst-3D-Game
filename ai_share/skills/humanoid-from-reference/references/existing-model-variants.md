# 既有模型變體：貼合、改色與局部避讓

適用於使用者明確要求沿用現有人物的外觀變體。參考圖用來約束指定部位和配色，不代表重建整套服裝或人體。下列方法來自 Roman T4；尺寸、顏色、UV 區域和權重必須按當前來源重新量測。

## 保留來源並建立獨立資產

- 複製各 LOD、manifest、bone-map 與 attribution，保留來源 hash。英雄使用獨立 descriptor、可修改的材質／貼圖副本；普通人物保持原樣。
- 只有需求包含尺寸改變時才離線等比縮放，再判斷是否需要局部體型修正。同步處理 mesh、node rest translations、inverse bind、socket、握持量測與動畫 position 軌；只改 mesh 會使關節和掛點錯位。輸出 root scale 維持 `(1,1,1)`。
- 量解剖頭頂與裸足面，不沿用 manifest 的含盔整體高度。每層重新量測；減面差異如實記錄。
- 檢查 loader 依 faction 套用的附件、材質修正、握持與合批。來源 GLB 專用的 hash/audit 或最佳化不能套到變體；用 descriptor 或明確相容性條件限制，不重寫 registry。

## 面甲先量臉，再塑外殼

1. 找出實際臉部皮膚 triangles，排除頭盔、頭內層及背面；記錄 brow、nose、cheek、lip、chin、jaw 的位置與橫截面。從外側向臉投射，確認座標與命中表面。只量包圍盒或用球面加鼻尖會做成長嘴或平板。
2. 以量測表面建立眉骨、鼻翼、顴骨、唇部與下巴的外殼轉折；對稱設計可取兩側較外的深度以保留安全間距。平滑只能去除量測噪聲，不能磨掉要求的臉部稜角。
3. 眼孔要是真實拓撲開口，含邊界和內壁；建立外殼、內殼和厚度後，檢查孔緣是否被厚度偏移推入皮膚。顏色依當次要求決定，不把金色眼框當預設。
4. 間距驗證不只量頂點：抽樣匯出三角面的內部，量「內殼到臉」的距離。粗三角形即使頂點都在外側，中間仍可能切入額頭／鼻尖；必要時局部細分或抬高，避免放大整張面甲。
5. 面甲作為 head 的剛性子件或 100% head 權重，各 LOD 都包含。保留原臉耳頸和頭盔；只修確定干涉的局部護頰。用瀏覽器正面及嚴格側面近照確認眉鼻頰下巴、眼孔、側面突出量與盔緣接合。

## Atlas 改色：先分類，再處理磨損

- 先確認材質、UV islands 和實際貼圖區域。皮膚／眼睛不跟隨盔甲改色；保留原 UV、法線與可辨識的磨損。不要把整張混合 atlas 乘上深色。
- 只用色相閾值找金色，會把銹斑判成金邊，也會漏掉被暖色或深色污染的鈕扣中心。以幾何用途和 UV 範圍為主，色彩遮罩為輔；小範圍形態學清理可去碎斑、填補金屬裝飾內孔。
- 修鈕扣或窄包邊時使用有界 UV 遮罩。Atlas 的不同 islands 可能緊鄰；無界 flood fill 或過度膨脹會跨到皮膚／布料。檢查輸出的影像，不只看遮罩運算是否成功；Pillow 轉出的 numpy view 可能唯讀，需要可寫副本。
- 黑鋼仍需能看清曲面；深色布料在中性照明下與金屬有區別。用 base color 和合理 PBR 參數達成，避免靠極端曝光或粗糙度遮掩錯誤。
- 同時看正面和背面。背後亮藍可能來自另一件內襯材質或真正穿模，不能只把正面 tunic 改深。低 LOD 的淺色斑也可能是減面後的 UV 邊界，不是皮膚：先查命中的 mesh／triangle／材質再改幾何。

## 肩袖、肘部與裙內襯的最小修正

| 部位／症狀 | 先確認 | 局部處理與驗證 |
| --- | --- | --- |
| 跑步時袖子穿護肩 | 護肩是否全綁胸骨、袖子卻隨上臂轉；rest 間距是否不足 | 只在接觸區做胸／上臂權重過渡及袖內間距；不要把整片胸甲綁手臂。驗證左右跑步極值、揮劍和騎乘 |
| 肩頭皮膚穿出 | 是皮膚命中、布料高光，還是粗 LOD 材質邊界 | 確定是袖內遮蔽皮膚才漸變內縮；保留原拓撲、權重及可見關節，不粗刪手臂 |
| 彎肘穿護腕 | 護腕近端相對 elbow 的位置，以及 upper/lower arm 權重 | 量出跨肘範圍，必要時縮短近端、保持腕端接點並用前臂權重。檢查伸直與屈肘，不能靠縮掉可見手肘修穿模 |
| 跑步／背面露出內襯 | 內襯腰口寬度、垂直圈數與 hips 到 upper_leg 的權重過渡 | 只增加必要中間圈、收窄遮蔽區並建立腰腿過渡；原外裙甲與接縫保持。各 LOD 分別檢查，不能假設同一頂點索引可共用 |

原有完整體表優先保留。以上避讓不等於即時碰撞；把有限動作取樣和來源既有的粗 UV、硬裙甲、死亡動作限制分開記錄。

## 可重製與驗證

Roman T4 的順序是 builder → retarget → audit。Builder 需要 Blender 的 `mathutils.geometry.delaunay_2d_cdt` 及具 Pillow／numpy 的 Python，可用 `ROMAN_HERO_BLENDER` 和 `ROMAN_HERO_PYTHON` 指定路徑。`roman-mask-topology.py` 與 `roman-hero-textures.py` 是 builder 的持續維護依賴，不是一次性探針。

重建從普通 Roman 的乾淨 GLB 開始；retarget 拒絕重複烘焙。離線地面校正須量實際蒙皮頂點，保留 clip 名稱、時長、事件與來源旋轉。只調英雄的騎姿或資產級 offset，不調坐騎物理。最後核對三層 GLB 的 hash、內嵌貼圖、面數、尺寸與完整 bindings，再用既有 DEV 預覽驗證普通人物、英雄與原英雄入口的隔離。
