# 連接區蒙皮診斷

用於硬甲、鏈甲與皮膚連在同一 mesh，動作時腿根、腹下或尾根出現扇形薄片、裂口或凹陷。先以 [動畫診斷](animation-deformation.md) 分清骨架、動作、蒙皮與播放問題；本文件處理表面分區和權重，並不預設要重建骨架。

## 把畫面缺陷對回來源

固定資產 SHA、clip／時刻、LOD 與相機，選一個能穩定重現的缺陷。將畫面命中的三角面追到來源面與其頂點，保留下面這組最小證據：

- REST 與 posed 位置、相鄰邊長的絕對增量／比例，以及需要時的面積、法線或截面。短邊的比例容易很大，不能單靠最大比例判定整體品質。
- 原始權重、各處理階段的權重、最終匯出權重，以及所屬表面／固定點類別。
- 原姿勢與相鄰時刻的實圖。金屬上的亮灰三角面可能只是反光；同一剛性控制下邊長不變，不能直接稱為裂片。反過來，一張面沒有拉長，也不能排除整片皮膚折疊或截面壓扁。

修前修後用相同骨架／動畫取樣。若骨長、rest、inverse bind 或動作也改了，先分開比較，避免把多項差異誤判為同一修法的效果。

## 分清幾何點、面角與表面用途

匯入 GLB 後，一個來源幾何點可能因 UV 或法線縫變成多個頂點。建立來源面、面角、同位置點與匯出頂點的對照；核對來源 hash、座標系、容差與數量，不能只憑頂點索引相同就當作同一點。

- 同一連續表面的 UV／法線複本要有一致權重，同時保留每個面角的 UV、normal。權重運算可共用幾何點，不能因此把不同面角屬性焊掉。
- 同位置但屬於不同獨立表面或接合部件的點，不一定共用權重；即使它們在同一 mesh 內，也要依來源連通性與實際接合辨識。若要拆硬甲與皮膚的頂點所有權，先證明自然分界並看動態接縫。拆頂點或複製背板不是通用補洞方法。
- 硬甲區要包含外面、內殼、翻邊與返回面。只修外殼可能讓內殼繼續受腿骨拉扯；用來源正反面／剖視核對完整區域，而非看外側輪廓就標記完成。
- 毛皮、硬甲、鞍座、柔性鏈甲分開判定。材質金屬度、顏色、位置範圍與原生權重都是線索，不能單獨當真實部位分類；例如尾孔旁鏈甲帶有尾骨權重，不代表它就是尾巴。

先把實際來源區域畫清楚，再調它的支撐。保留未確定區域與原因；舊遮罩名稱如「groin」「native」「complete」不等於已完成解剖或表面驗證。

## 追查最後一次覆寫

對缺陷點及邊界兩側建立簡短的權重追蹤：來源 → 軀幹／腹帶 → 裝甲核心 → 過渡平滑 → 核心恢復 → influence 截斷／匯出。依實際 builder 階段調整，不要求套這個順序。

重點是找出**哪一階段第一次把正確的部位支撐改壞**：

- 軀幹／腹帶區可能與內側大腿、腋下重疊，把近端腿權重重新蓋成軀幹；剛修好的點也可能被最後的 native／rigid restore 蓋回去。核對最後的固定集合和輸出，不能只驗中間遮罩。
- 原生自動權重可能保留有用的腳掌／腿幹支撐，也可能把鏈甲誤配給尾骨。只保留已核對的部分，不把全部 native 視為正確或全部丟棄。
- 查看軀幹、上腿、小腿的過渡是否合理。皮膚只在身體與小腿間混合時，要查是否錯失上腿參與；不能從局部取樣直接推論整條大腿沒有權重。
- 在連通的近端表面建立支撐與過渡，包含原本腿權重為零的鄰點。膝上腿管與中央跨腿腹股溝是不同部位；不將整片腹股溝剛性綁到軀幹或單側腿，也不靠幾個孤立硬點修出新的尖角。
- 骨段射線沒命中毛皮，先查硬甲遮擋、命中順序及來源表面。沒有中股骨截面命中，不能證明膝上皮膚不存在或不該受股骨支撐；需要來源形狀證據，不能憑空添加硬核心。

## 平滑之前先檢查邊界是否可行

Harmonic／其他平滑只能在給定支撐之間分配權重，不能把錯誤的解剖邊界變對。

| 檢查 | 影響下一步的結果 |
| --- | --- |
| 實際固定點類別、自由區及最後恢復順序 | 查「native 保護」「區域外固定」「軀幹固定」是否悄悄留下錯誤支撐 |
| 相鄰固定點與穿過自由區的來源連通路徑 | 若姿態下兩端距離超過來源路徑總長，該路徑必須伸長；只擴幾圈或增加迭代無法消除矛盾 |
| 每個自由連通區是否有有效邊界 | 找不到支撐時應回報區域與來源；不要默默載入舊候選權重，破壞可重建性 |
| 解的殘差／收斂及邊界是否保持 | 固定迭代次數不是收斂證據；但數值收斂也不證明解剖或視覺正確 |
| 原始權重先驗與完整輸出場 | 先驗可能保留來源錯誤，也可能保護原有腿形；無先驗對照可用於診斷，不是所有模型都該改成零先驗 |

一次改一個可由證據支持的原因，用原缺陷姿勢判斷。若同一薄片仍在，先更新來源面、支撐或量測證據，不繼續掃平滑係數、圈數與硬點數。無法由權重解決時，回頭查來源活動空間、表面結構與動作；有證據後才在任務範圍內改幾何或姿態，不以額外遮洞面掩蓋問題。

## 區分完整權重場與四骨截斷

當 solver 保留的 influences 多於 runtime 可用數量時，在**相同姿勢、相同幾何、相同 bind** 比較完整權重場與實際匯出 top-4 的 posed 位置及局部形狀。

- 完整場已拉扯或折疊：先修表面用途與支撐，不能把 top-4 當主因。
- 只有截斷後壞掉：量測最大丟棄權重、實際位置偏差及相鄰點連續性；不要只看權重總和等於一。
- 合併等價骨影響須證明相關 clips 中的 skinning 變換等價；同名、同父骨或 REST 相同都不夠。
- 單一跑姿擬合得更好不代表其他動作也好；重新檢查受影響 clips、極值及循環接點。不要為局部試驗直接增加每個 runtime 頂點的骨影響數。

## 重建與成品驗收

- 確認工具、來源、區域資料、依賴版本與輸出一致。Blender batch 應讓 Python 失敗回傳非零退出碼（例如 `--python-exit-code 1`），並核對本次輸出 hash／report，避免舊檔仍在而被當成新成功。
- 快速迭代只重跑需要的階段；保留乾淨來源與已驗骨架／動畫 checkpoint。不要在已拆過面、已平滑或已做接地修正的候選上再次疊整套處理；最終執行可由來源重建的正式流程。
- 重新解碼最終壓縮 GLB、檢查各 LOD 和關鍵幀之間。LOD 若已移除來源端點，不能用最近頂點冒稱「同一條邊修好了」；分開報同拓樸比較與成品實際畫面。
- 同時記錄改善與殘餘問題。結構有效、loader 可載入、測試成功不等於薄片消失；看到局部改善，仍要回到原失敗視角及相鄰動作驗證。

## 雪豹案例的依據與限制

[PR #396](https://github.com/Andy-CH-BO-AN/SagaBurst-3D-Game/pull/396) 的合併紀錄指出：軀幹／腹帶處理覆蓋了部分近端腿權重，修復保留來源拓樸並補回上段骨參與與局部過渡。這不是「全模型沒有大腿權重」或「native bind pose 錯配」的證明。該版仍列出腹下連接薄帶拉伸、幀間穿地及遊戲／GPU 未驗證，不能將它引用成完整美術通過。

繼續處理此資產時讀目前的 [builder](../../../../tools/blender/build_snow_leopard.py)、[來源區域](../../../../tools/blender/snow_leopard_skin_regions.json) 與 [audit](../../../../public/models/mounts/v2/snow-leopard/audit.json)，並核對其對應 GLB hash。歷史試驗的零先驗解、拆分所有權或候選膝上硬點，不是已驗證的標準配方；不要複製案例骨號、座標、權重比例或平滑係數到其他來源。
