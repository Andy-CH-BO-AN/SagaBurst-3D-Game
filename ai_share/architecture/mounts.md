# 坐騎

範圍：Mount 行為、四足坐騎資產、馬甲、衝撞傷害、巨鷹與騎乘落馬。索引與共通規則見 [ARCHITECTURE.md](../ARCHITECTURE.md)。

- `Mount` 是 HP、移動、碰撞、跳躍、衝撞、死亡／下馬與存檔的權威；`HorseAssetRegistry`、`BlackCatVisual`、`SnowLeopardVisual`、`CorgiVisual`、`XongkoroVisual` 負責資產與動畫，保留原 save IDs。
- `QuadrupedAssetPreload` 集中 Black Cat／Snow Leopard／Corgi 的 manifest／GLB 驗證、並行預載共用與失敗重試；各 Visual 提供路徑、body 前綴與模板發布。全部必要 clips／LOD／seat 通過後才發布模板，失敗後下次預載重新讀取，Black Cat 與 Snow Leopard 的實例、LOD 及動畫共用 `QuadrupedVisual`；Snow Leopard 必須具備完整七段 baked clips。
- 地面坐騎只有 LOD0 投射陰影：戰馬依 `HorseShadowPolicy` 名單，Black Cat／Snow Leopard 由 `QuadrupedVisual` 依 LOD level 設定（LOD1/2 不投影）。
- 戰馬與 Black Cat／Snow Leopard 共用 `CharacterLODPolicy.mountAnimationInterval`（>35m 15Hz、>55m 6Hz 推進 mixer）；`QuadrupedVisual` 不再強制更新整棵世界矩陣。遠距騎士在坐騎姿勢未推進時，由 `SkinnedSeatContact.reapply` 沿用上次量得的座位修正。近距離的 `align` 只更新取樣頂點所用的骨鏈（attached bind 的世界座標不需要 mesh 矩陣）；`Game` 主迴圈在算繪前以 `fitMountedSeat(false)` 略過騎士子樹刷新，其他呼叫者照常立即刷新。`CharacterEquipmentPose.apply` 每次結束都會整棵刷新角色；它從不寫入 rig root 與其祖先，因此進入時只刷新一次 root 鏈，之後的世界查詢（含其 `ArmSolver`、`FittedHumanoidCloth`）都經 `AnchoredWorldMatrix` 從 root 往下刷新，逐節點運算與 Three 的整鏈走訪相同、結果逐位元一致；中途只有直接讀取子孫 `.matrixWorld` 的分支才需要先刷新子樹。Three r167 的 `getWorldPosition`／`getWorldQuaternion`／`localToWorld`／`worldToLocal`／`lookAt` 每次都會重算到 scene root，沒有髒標記；熱路徑在確定祖先未變時改用 `AnchoredWorldMatrix`（錨點往下、或 `refreshWorldChains` 合併多個節點的共同祖先），只在呼叫者能保證期間沒有寫入那些鏈時使用。主 rig 剛整棵刷新後的 `onPoseEvaluated(true)` 讓裝備 socket 略過重走手部父鏈。
- `ARMORED_HORSE`／Career ID `armored-horse` 是獨立重甲戰馬，使用 `HorseAssetRegistry` 的獨立模板、原戰馬 70 骨架／九動畫與三層 LOD；不替換普通馬。10.5 m/s、HP 600、售價 8,000 軍功，重甲馬的加速／轉向限制在既有 `Mount` controlled movement owner 處理，Player／NPC 共用。
- `MountArmor` 以獨立 `ShieldState` 重用 `absorb()` 和 `weaponShieldImpact()`：重甲馬／雪豹 50 Impact，其餘 0。`DamageRouter.damageMount` 只對武器 melee／projectile 消耗護甲；自然鷹擊、墜落、地形與 mount-impact 沿原 HP 路徑。騎士 body／盾接觸不消耗馬甲，也不受馬甲保護。Game 與 Town 所有武器命中坐騎的 caller 都須保留武器 ID／攻擊者騎乘狀態。
- 玩家馬甲耐久在 `CareerProfile.mountArmor`、任務 `mountState.armorImpact` 與 mounted RPG save 保存；NPC／借用角色在既有 mount resource checkpoint 保存 `armorImpactRemaining`，決鬥、賽馬的既有資源快照亦保留。現行耐久狀態按 writer 保存，已存 0 必須保留；只有 respawn／正式 refit／rest 重設。純護甲受擊也須觸發資源 checkpoint。
- `calculateMountImpactDamage` 先保留原四捨五入的基礎公式，再套重甲馬／雪豹 2.5、其他 1；Player 的 Mounted Impact skill 再由原 caller 加成。`skipImpact` 與冷卻不改；Game／Town 成功撞擊步兵後共用短距 swept obstacle／地形／world-bound 檢查的擊退，不對騎士／坐騎重複結算。
- `MountStats`（`src/combat/`）是各坐騎基礎速度、最大 HP 的唯一資料來源，並組合 `MountArmor`、`XONGKORO` 的護甲／撞擊倍率／飛行數值；`Mount` 建構子與騎手速度例外（重甲戰馬僅拜占庭鐵甲重騎兵 `heroAssetId` 為 12 m/s，其餘 10.5）直接讀取它。`MountComparison`（`src/rpg/`）以純函式產生背包／坐騎商店的能力比較：基準為目前騎乘、否則目前分配，無基準或候選即基準時不宣稱強弱；巨鷹與地面坐騎一律「各有取捨」，不以飛行速度排名。比較只用最大 HP／護甲上限，不用目前耐久；兩處 UI 不建立 `Mount` 或模型。
- 坐騎實例共享 render resources、各自持有 skeleton／mixer。Horse LOD 與遠距動畫節流由 registry 維護；不改變 gameplay timer。
- Black Cat／Corgi 使用 `idle`、`walk`、`run`、`death`，保留遊戲會呼叫的 `jump`／`land`／`hit`；`QuadrupedMountAnimation` 定義種類與速度遲滯，Horse 保留原步態。各實例的全部 LOD 共用一套 skeleton／mixer，死亡單次播放後停在末幀；一次性受擊／落地結束後恢復最新請求的步態與播放速度。
- 騎士骨盆對準解剖 seat socket，腿姿遵循各 rig 的 `forwardBendSign`。Black Cat／Snow Leopard／Corgi 的座面接觸由 `RiderSeatContactCache` 依騎手 visual child 身分快取；換裝重建模型時失效，不能沿用已脫離 mesh 的世界高度。Corgi 的 `CorgiSeatContact` 修正座面貼合；DEV 校準是否適用正式 Player/NPC 必須依實際呼叫端確認。
- Custom Battle／Defense Campaign 的 Player 可選坐騎；一般戰場騎兵與營地預設 Horse。Career 的駐軍、英雄與商人坐騎由城鎮規則決定。
- Game 玩家武器、徒手近戰與騎乘衝撞（`resolveMountImpacts` 玩家坐騎分支）的 NPC 目標共用 `isPlayerHostileNpc`（ENEMY、BANDIT 與敵對 Town），與 player-hostile grid 同一規則；友軍與死亡目標排除。
- 近戰與投射物沿用 `WeaponSweep`／`traceCombatSegment`，比較 shield、人物 body 與 mount 的 first contact。Mount collider 使用 aim proxy 的 local box，隨完整 world transform 旋轉／縮放；所有存活坐騎都是獨立 physical target，無 rider 或同陣營仍阻擋並承受武器命中，NPC 不主動選無騎士坐騎為目標。攻擊者自己的坐騎排除於自己的武器查詢。
- `CombatContact.mount` 指向真正命中的坐騎。body／盾牌 overflow 只傷人物，mount 只傷坐騎；兩者死亡獨立、正常 release rider。`mount-impact` 是明確例外：目標騎乘存活坐騎時傷坐騎，否则傷人物，不判 first contact、不吃盾。未帶 contact 的 scripted damage 傷指定人物，不因 mounted 轉移。長槍 charge 與 mount impact 避免同次重複傷害；死亡坐騎仍需完成動畫更新。
- 戰場坐騎 HP 傷害與 NPC HP 傷害皆沿用 CombatEvent offensive XP；傷害數字只顯示 actual appliedDamage，HUD 對應實際命中對象。Player 的 mount HUD 由仍然 mounted 且 currentMount 存活決定，不由上一擊 isMountHit 決定。
- `xongkoro` 是 Tier 4 英雄坐騎。`XongkoroConfig` 集中 200 HP、48／96 km/h、起降／高度／射界與主動攻擊參數；`EagleFlightController` 接收 Player／`EagleFlightAI` 共用意圖，執行有限轉向、連續位移碰撞及完整起降淨空。`ThirdPersonCamera` 單獨消費滑鼠 delta，由 `EagleFlightAim` 同時產生準星與飛行意圖；瞄準維持巡航。
- `XongkoroVisual` 使用本地 CC BY 4.0 GLB：固定參考姿勢的頭身尾長度 10 m、+Z forward、MASK 羽毛材質；獨立 skeleton／mixer／程序化頭爪 pose；落地以來源腿鏈建立雙腳支撐並維持展翼的姿勢，依蒙皮腳底一次校準，起降平滑混合回飛行取樣。軀幹／頭部受擊 proxy 跟隨同一骨架；低空依淨高限制拍翼幅度，拍翼聲由 `WingbeatPhaseTracker` 追蹤動畫下拍，`EagleWingbeatAudio` 將 Game／Town 的實例接至既有 SoundManager，依距離與數量預算播放本地音檔；音效不控制動畫或 gameplay。`StandingRider` 在飛行 transform、動畫及姿態後對齊軀幹 standing socket 與雙腳，不把坐騎縮放傳给騎手；Player／NPC 保持 mounted，使用獨立下半身站乘姿勢。
- 巨鷹 render bounds 由 `tools/build-xongkoro-bounds.mjs` 離線推導並保存在 `render-bounds.json`；依正式蒙皮、骨鏈位移／縮放上界、地面支撐與攻擊伸展建立涵蓋連續混合的保守包絡。共享預載驗證 GLB、姿勢來源及全部 render mesh 契約後，`XongkoroVisual` 在 LOD 重掛後轉為各實例私有的 mesh-local `SkinnedMesh.boundingSphere`，讓主畫面與陰影各自裁切。資料缺失或過期時保留不裁切並提供警告；預熱保留非空 bounds，restore 沿用同一實例。這個邊界只決定繪製，不控制模擬、socket 或受擊範圍。
- `EagleAttack` 只在主動窗口掃掠頭／爪，按 attack instance 去重、先判盾／人體／坐騎實際 contact；飛行坐騎排除被動 `MountImpact`。攻擊 method 為 melee、來源 metadata 為 `xongkoro`，技能歸屬 mountedImpact，與手持武器無關。
- `FallingRider` 共用腳底最高點、繼承速度、重力與有效支撐面落地規則；解除綁定冪等，死亡角色仍完成墜落。`fall` 環境傷害繞過戰鬥減傷，以 rider.maxHp × h / 15 結算一次，h ≥ 15 必死；經正式 HP／死亡回呼與歸因事件，不給武器 XP。死鷹先墜落接地再淡出。`CareerAerialState` 與普通 `SaveManager` 保存未決墜落及飛行／戰損，合法退出清除舊場景 callback。
- 授權、來源雜湊與重建方式保留於各模型目錄的 manifest／CREDITS 及必要 provenance；製作／匯出驗證由資產 skill 維護。
