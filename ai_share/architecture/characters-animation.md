# 角色資產與動畫

範圍：人物資產 registry、普通士兵／英雄職業、LOD、戰鬥動畫事件與裝備姿勢。索引與共通規則見 [ARCHITECTURE.md](../ARCHITECTURE.md)。

- 軍用 `viking-hero-t4`／`viking`／`roman` 使用交付來源的 63／22／54 骨與 11 段動畫；以離線名稱／原點正規化及明確 `selectedSource` 契約接入，不冒用 T5 來源骨架。三 LOD 沿用 `SelectedLodPose`，同角色相同 joints／inverse bind 的多 mesh 共用 Skeleton，不同角色不共用可變骨骼。居民與商人由 `CharacterVisualConfig.civilian` 及 `civilianStyle ?? faction` 選擇 `roman-civilian`／`viking-civilian` 的獨立來源模型。
- 三套新模型的完整長斧頭來源動作透過既有 manifest `meleeCycleSeconds`／events 轉換到 gameplay clock，再套原裝備與英雄攻速；不截短來源片段。Roman 動態雙手斧 socket 與來源校準的斧頭握點在 mixer 後同步到正式武器 pivot，物理握點／刀尖使用相同 transform。生成的受擊 overlay 不取消攻擊事件或修改傷害。
- 普通士兵的身分與裝備分開：`OrdinarySoldierProfile` 共用 Roman T1/T2/T3 基礎 HP 100/150/200、Viking 90/135/180，Player 保留一次既有技能加成。Career 的正式 Recruit/Soldier/Veteran 決定 T1/T2/T3，Captain/Commander 仍是原英雄；武器、護甲和臨時借裝不改正式身分。未指定的普通士兵預設 T2，平民及特殊角色不進普通表。`CharacterIdentity` 集中解析正式 `characterTier`（1–5）、`heroArchetype`、文化陣營與模型／Profile；既有 `tier` 僅作舊 roster 轉接，T5 的舊 tier 4 由已登記的 Commander asset／Profile 解析，明確衝突拒絕。
- Roman/Viking T1/T2 使用 `roman-t1`、`roman-t2`、`viking-t1`、`viking-t2` 獨立資產；T3 保留原 faction template。四資產預載、三個 LOD 共用既有載入／動畫／socket 管線；重建與來源見 `tools/tiered-faction-soldiers.md`。手指只從原手部權重重新分配，禁止把衣物權重轉到手指。四資產以 manifest opt-in 保留 mounted 上半身的 canonical 指骨軌，並對實際向前槍／騎乘劍軸校準右前臂，equipment proxy 反向補償保留武器世界姿勢；Roman T1/T2 自由左手沿既有解剖前臂校正保持拇指朝前，盾／弓／雙手接觸各保留原 owner。
- 一般 RPG 存檔使用 `sagaburst_game_v2`／version 2，完整保存 HP／最大 HP、正式身分、自訂 HP 來源、背包、六技能、坐騎位置及飛行／未決墜落。只按保存的現行最大 HP 還原資源，不換算歷史 Career HP、不由舊武器清單補背包、不由騎士座標補坐騎。自訂戰鬥與防衛戰役重整分別使用 `sagaburst_battle_config_v2`／`sagaburst_campaign_config_v2`，只存正式 preset IDs 與明確 HP 來源；獨立防衛關卡進度 `sagaburst_defense_campaign_progress_v1` 未改格式，保留原 key。Web／Electron 共用相同契約與原 origin；不雙讀、刪除、覆寫或遷移舊 key。
- `HumanoidAssetRegistry` 在產生角色前載入可用 manifest／GLB；正式模式不以舊程序人物靜默替代失敗資產。`HeroAssetCatalog` 集中 T4／T5 描述，`SETUP_PLAYER_HERO_IDS` 另限制自由模式的選角。`HeroCombatProfile` 共用 Player／NPC 的英雄數值，Player 技能由原管線套用一次，NPC 不套玩家技能。實例銷毀及 render warmup 結束釋放各自的 skeleton bone texture，保留共享 geometry／material／texture。 選定 T5 的三個 LOD 經 `SelectedLodPose` 驗證相同骨架 bind 與動畫樣本後，共用單一角色的骨架／mixer；不同角色仍擁有獨立可變狀態。來源 raw clips 保留，runtime 只略過每段來源動畫中均等於 bind 的不變屬性。
- Fitted civilian／Shadow 的三個 LOD 以 `sharedLodPose` 驗證同一 bind／動畫並共用單角色 pose；各 LOD 內嵌完整動作。明確 `bufferCompression: EXT_meshopt_compression` 的資產由既有 Three 隨附 MeshoptDecoder 載入，離線包裝不量化 geometry／skin／animation；PNG 重壓保留解碼像素。沒有額外 decoder URL 或新網路依賴。一般 preload 不載平民；Town 由實際 roster 推出所需 civilian factions 並在建立居民前 await，包含敵境原生人口與借用居民。
- geometry、material、texture、clip 共用模板；每個角色持有獨立 skeleton、mixer、socket 與動作狀態。`CharacterVisuals` 提供共用 `CharacterRig` 契約及舊測試模型。
- `HUMANOID_LOD_DISTANCES` 是人物 LOD 門檻的唯一來源。LOD0 是裝備 socket authority；穩態求值 LOD0 加可見 LOD，切換、fade、seek 必須補齊姿勢／時間，不能重播 gameplay 事件。
- 距離節流只減少視覺求值；AI、移動、攻擊事件與 gameplay timer 每幀推進。跳過的 visual dt 只能補算一次。
- `CharacterCombatAnimator` 擁有一次性攻擊／釋放事件；Player/NPC 在事件到達時造成傷害或產生投射物。完成或取消後回到最新 locomotion，換裝取消未完成動作、不補發事件。NPC 非戰鬥時使用一般站立／移動／騎乘 locomotion，不自動套用持弓準備姿勢；失去瞄準時解除搭箭與弓身蓄力，真正戰鬥瞄準、放箭及收招維持原事件流程。
- 徒步單手斧／戰槌由實際裝備的 `animationKind` 選擇共用 `axeAttack1HFoot`，不以斧頭 mesh 判斷；騎乘及雙手仍走原 action。已選定模型使用原有 Bandit 適配 clip，保留的 Roman hero 在 registry 預載時由 `BanditFootAttack` 從同一 Bandit 來源產生共用模板，新 fitted 居民／Shadow 已離線內嵌同源 retarget；保留原單手事件時鐘與 idle 骨盆／腿，不增加 GLB 或每角色 retarget。
- `CareerProfile.eliteClass` 是獨立於五級軍階的進階職業；拜占庭只接受 Roman Captain／Commander 的本次服役累積 30,000 軍功，不扣除餘額。直接由 Captain 任命只走一次原 Commander 獎勵；既有 Commander 改轉不重發。`CareerElitePromotion` 擁有資格與 staged profile，Town 先預載並建立候選角色，再保存；失敗保留原角色。`byzantine-cataphract-t5` 對應獨立 Profile，暫時明示沿用真實 Roman T5 資產，待使用者交付專屬 GLB。
- T4／T5 職業是兩條同規則的 `CareerClassRoad`（`CareerElitePromotion` 的 `classRoadOffer`／`applyClassRoad`；`T4_CLASS_ROAD`、`T5_CLASS_ROAD` 只擁有各陣營職業清單、門檻／價格與存檔欄位）。T4 存 `t4Specialization`／`unlockedT4Classes`（羅馬 聖騎士 5,000／百夫長 7,000，維京 瓦良格隊長 5,000／龍誓重衛 7,000），T5 存 `eliteClass`／`unlockedCareerClasses`（羅馬 指揮官 20,000／拜占庭 30,000，維京 指揮官 20,000／鐵血戰帥 30,000；陣營預設存為 `eliteClass: null`）。首次任命依本次入伍軍功免費，第二職業以可用軍功永久解鎖、免費切換；通用 `canAppointCareerRank` 不處理 Veteran→Captain 與 Captain→Commander。任命 writer 必須保存明確職業與永久解鎖紀錄；跨陣營、跨道路、重複或首次門檻不足的紀錄被拒。職業→英雄資產由 `CareerPlayerProfile` 的 `T4_CLASS_HERO`／`CAREER_CLASS_HERO` 對應；百夫長、龍誓重衛、鐵血戰帥僅 Career 玩家或明示的 identity 使用，NPC 預設 T4／T5 不變。升 T5 後外觀與數值完全依 T5，T4 紀錄僅保留為存檔資料。重甲維京（`dragon-oathguard`、`ironblood-warlord`）移速倍率 1.0，與既有公式一樣同時作用於步行與騎乘。
- 所有 `*_heavy_cavalry` 的 T4／T5 在各模式固定使用重甲職業：`T4_UNIT_PROFILES` 為百夫長／龍誓重衛，`getT5ProfileForPreset` 為拜占庭鐵甲重騎兵／鐵血戰帥；盾牌依陣營決定、不隨人物資產改變，其他兵種不變。`heavyT4Variant` 供 Commander IV 隊長交替與 Captain IV 敵方前鋒取得重甲 T4，Ranger 保留遊俠身體。Town 士官長 `deployment` 是 T5 重騎兵指揮官（`characterTier: 5`，roster 仍為 T4 紀錄與步兵小隊成員），雙方巡邏隊長為重甲 T4，Captain 與 Town Commander 維持原職業。士官長武器／盾牌 native token 仍為原 T4 identity，僅在持有預設 token 時以 T5 class kit 覆蓋；坐騎使用現行 native token，與其他原生裝備一樣保存持有人／reserve／售出狀態，不在載入時補發。
- `CareerHeroClasses` 是兩個陣營 T4 Captain／T5 Commander 各兩個職業（預設＋重甲）與中文職業名稱的唯一來源，重甲身體取自上述共用 T4／T5 Catalog。HR 私兵以 `PersonalHeroVariantAssetId`（`roman-centurion-t4`／`viking-heavy-hero-t4`／`byzantine-cataphract-t5`／`viking-heavy-hero-t5`）明確保存重甲身分，只限本陣營、Captain／Commander；T4 重甲維持 500 軍功，T5 重甲 3,000 軍功（與玩家 7,000／30,000 的職業解鎖無關），身分不由裝備推斷。1v1 Duel 的 T4／T5 在兵種與 Tier 之後多一步職業選擇（`CareerDuelClasses`；T4 弓兵保留 Ranger），選擇存為 `activeMission.duelClassId`，缺值或不合法時沿用居民原職業；通關進度仍只按 preset＋Tier。居民無法就地換身體，非原職業由 `CareerDuelController` 以場景提供的 factory 生成暫時對手（同 combatantId、全新生命值），原居民隱藏停放且不被修改，結算或 cleanup 時銷毀暫時身體並恢復居民。
- `InventoryManager.activeMelee` 只回傳實際取出的近戰武器，空裝備不 fallback 長槍；Career 的空裝備選擇跨任務與讀檔保留。拳擊為獨立 `punchCombo`／`punchRight` action，由 Animator 單一時鐘發出四個程式動作接觸事件。`CharacterEquipmentPose` 在所有 LOD 共用手臂求解，持盾保留左臂；`UnarmedCombat` 用實際掌部軌跡追蹤盾／人物／坐騎，接既有傷害歸屬及獨立第六技能 `unarmed`，且不呼叫結構破壞。徒手 Lv.1–50 的傷害曲線為 ×1–5，每點實際 HP 傷害只由權威傷害事件發放 2 XP；既有武器技能仍為 ×1–3，徒手每級 +1 HP（Lv.1 不額外加血），新角色與技能 writer 保存六個技能，讀檔不轉換 `archery` 或補齊歷史技能。Town 與 Game 共用事件歸屬判定，Town 不再從命中函式重複手動發放攻擊 XP。Punch_Combo_1 匯入與外觀驗收待 GLB 階段。有效拳頭傷害以 `attackSource: unarmed`／`weaponId: unarmed` 識別，Game／Town 共用音效判定；`SoundManager.playPunchHit` 使用可選 public URL 與共用 impact voice budget，缺檔每個 manager 僅嘗試一次。
- `InteractionFocus` 與 `PickupPrompt` 讓 Game 及越獄共用地面互動選擇與提示：朝向優先、近似分數維持焦點，E 只作用於先前顯示且仍在距離內的同一目標和動作；`PlayerInput` 只接受實體按下邊緣。Game 的坐騎與拾取共用選擇，只有正式自訂戰鬥可在實際配置槽為空且不干擾既有配裝時自動裝備；其他 Game 模式仍收進背包。越獄保留獨立劍歸屬與先保存再裝備，開門、倒下、倒數或保存重試期間不提供拾劍提示。
- `CharacterEquipmentPose` 在 mixer 後套姿勢，下一次求值前還原。`bakedEquipmentActions` 表明已烘焙握點的動作，避免疊加通用 IK；資產與 runtime 不能同時擁有同一關節修正。
